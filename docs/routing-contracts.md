# Routing implementation boundary

The [portable routing contract](../src/llm_router_eval/shared/routing/README.md) describes all seven variants, typed question shapes, bounded integer grammar, strict public input, consumed-span accounting and calibration fallback. These policies currently use explicit caller callbacks. A full Provider/Ledger-to-policy runner and licensed-data evaluation remain pending.

The code tier follows the selected plan's narrow integer addition/multiplication grammar. Broader conversion/date/string handlers from the alternative plan are deferred MVP scope. Six policy families retain both checker variants as seven executable rows. Missing calibration causes unconditional escalation, not an automatically chosen higher threshold. The synthetic test permits are implementation controls and cannot authorize real cheap acceptance or support measured quality claims.

No benchmark, hidden-label tuning, live inference, model quality, latency or savings result is established by the routing unit or detached-source tests.
